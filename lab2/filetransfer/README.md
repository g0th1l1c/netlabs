# filetransfer — передача файла по TCP

Клиент и сервер на Go для передачи произвольного файла с одного компьютера на другой.
Сервер принимает несколько клиентов параллельно и показывает скорость приёма.

## Структура проекта

```
filetransfer/
├── go.mod
├── README.md
├── cmd/
│   ├── server/main.go        # точка входа сервера
│   └── client/main.go        # точка входа клиента
└── internal/
    ├── protocol/protocol.go  # формат заголовка, константы, чтение/запись
    ├── server/
    │   ├── server.go         # приём соединений, обработка клиента
    │   ├── storage.go        # безопасное имя файла, создание файла в uploads/
    │   └── speed.go          # подсчёт и вывод скорости
    └── client/client.go      # отправка файла и получение ответа
```

## Сборка

Нужен Go 1.24 или новее.

```bash
go build -o bin/server ./cmd/server
go build -o bin/client ./cmd/client
```

## Запуск

Сервер (порт — единственный параметр):

```bash
./bin/server 9000
```

Клиент (путь к файлу, хост или IP, порт):

```bash
./bin/client ./video.mp4 localhost 9000
или 
.\bin\client.exe test.txt localhost 9000
или
.\bin\client.exe big.bin localhost 9000
или
  .\bin\client.exe big.bin 127.0.0.1 9000
```

Сервер сохраняет файлы в поддиректорию `uploads/` текущей директории
(создаётся автоматически). Остановка сервера — `Ctrl+C`: он перестаёт принимать
новые соединения и дожидается завершения текущих передач (повторный `Ctrl+C` — выход сразу).

## Пример вывода сервера

```
2026/10/03 12:00:00 сервер слушает [::]:9000, файлы сохраняются в "uploads"
2026/10/03 12:00:05 [клиент #1 127.0.0.1:51234] подключился
2026/10/03 12:00:05 [клиент #1 127.0.0.1:51234] принимаю "video.mp4" (734003200 байт) -> uploads/video.mp4
2026/10/03 12:00:08 [клиент #1 127.0.0.1:51234] мгновенная: 412.50 МиБ/с, средняя: 412.50 МиБ/с (принято 1297612800 байт)
2026/10/03 12:00:09 [клиент #1 127.0.0.1:51234] передача завершена успешно
```

Если клиент был активен меньше 3 секунд, скорость выводится один раз в конце приёма.

## Протокол

Все числа — big-endian. Используется один TCP-сеанс на один файл.

**Клиент → сервер**

| Поле          | Размер        | Описание                                  |
|---------------|---------------|-------------------------------------------|
| Длина имени   | 2 байта       | `N`, от 1 до 4096                         |
| Имя файла     | `N` байт      | UTF-8, без пути (только имя файла)        |
| Размер файла  | 8 байт        | `size`, от 0 до 1 ТиБ (2^40 байт)         |
| Содержимое    | `size` байт   | байты файла                               |

**Сервер → клиент** (после приёма всех данных)

| Поле   | Размер | Описание                              |
|--------|--------|---------------------------------------|
| Статус | 1 байт | `1` — успех, `0` — ошибка             |

После отправки статуса сервер закрывает соединение.

## Как выполнены требования

- **Порт сервера** и **путь/хост/порт клиента** передаются аргументами командной строки.
- **Имя файла** — клиент отправляет только последний элемент пути в UTF-8 (до 4096 байт).
- **Безопасность:** сервер берёт из присланного имени только последний элемент пути
  (учитываются и `/`, и `\`), заменяет запрещённые символы на `_` и не принимает
  `.`/`..`. Файл создаётся строго внутри `uploads/`. Существующие файлы не перезаписываются:
  при совпадении имени добавляется суффикс (`name_1.ext`, `name_2.ext`, ...).
- **Скорость:** для каждого клиента раз в 3 секунды печатаются мгновенная и средняя скорость;
  если приём длился меньше 3 секунд — один раз при завершении.
- **Проверка размера:** сервер сравнивает число принятых байт (и размер файла на диске)
  с размером из заголовка и отправляет клиенту статус успеха или ошибки.
- **Параллельность:** каждый клиент обслуживается в отдельной горутине
  (аналог потока); сервер сразу возвращается к `Accept`.
- **Ошибки:** при любой ошибке с клиентом (обрыв, неверный заголовок, ошибка диска,
  таймаут простоя 30 секунд) сервер удаляет недокачанный файл, закрывает это соединение
  и продолжает работать с остальными клиентами.
- **Ресурсы:** соединения, файлы и listener закрываются через `defer`/явно сразу после использования.
- **Лимиты:** размер файла до 1 ТиБ проверяется и клиентом, и сервером.

## Быстрая проверка

```bash
./bin/server 9000 &
head -c 100M /dev/urandom > /tmp/test.bin
./bin/client /tmp/test.bin localhost 9000
cmp /tmp/test.bin uploads/test.bin && echo "файлы совпадают"
```
