# Places — поиск интересных мест

Приложение на Go с интерфейсом в браузере. Вы вводите название (например, «Цветной проезд»),
выбираете одну из найденных локаций и получаете **погоду** и **интересные места
рядом с описаниями** — одним общим отчётом.


## Используемые API

| Что делаем                  | Сервис        | Метод                         |
|-----------------------------|---------------|-------------------------------|
| Поиск локаций по названию   | GraphHopper   | Geocoding (`/geocode`)        |
| Текущая погода по координатам | OpenWeatherMap | Current weather (`/weather`) |
| Интересные места в радиусе  | OpenTripMap   | `/places/radius`              |
| Описание места по `xid`     | OpenTripMap   | `/places/xid/{xid}`           |

Нужны три бесплатных ключа (регистрация на сайтах сервисов).
Новые ключи OpenWeatherMap активируются не сразу — иногда до 1–2 часов.

## Быстрый старт

Требуется Go 1.27.1 или новее. HTTP-библиотека: axios4go v1.0.0.

```bash
cp .env.example .env      # впишите ключи в .env
go run ./cmd/places
```

Ключи можно задать и обычными переменными окружения
(`GRAPHHOPPER_KEY`, `OPENWEATHER_KEY`, `OPENTRIPMAP_KEY`) — они важнее файла `.env`.

Сборка и тесты:

```bash
go build -o places ./cmd/places
go test -race ./...
```

## Как пользоваться

```
Введите название места: цветной проезд
Найдено:
  1. Цветной проезд, Москва, Россия
  ...
Выберите номер (0 — новый поиск): 1
```

Браузер открывается автоматически при запуске. Если этого не произошло, откройте адрес из терминала. Кнопка «Отменить загрузку» прерывает текущий запрос. «К вариантам» возвращает к списку локаций. `Ctrl+C` в терминале завершает локальный сервер.

## Настройки (необязательные)

| Переменная         | По умолчанию | Смысл                                      |
|--------------------|--------------|--------------------------------------------|
| `PLACES_RADIUS_M`  | 1000         | Радиус поиска мест, метры                  |
| `PLACES_LIMIT`     | 10           | Сколько мест показывать                    |
| `PLACES_PARALLEL`  | 5            | Сколько описаний запрашивать одновременно  |
| `HTTP_TIMEOUT_SEC` | 10           | Таймаут одного HTTP-запроса                |

## Структура проекта

```
cmd/places/main.go        точка входа: собирает всё вместе и запускает
internal/
  config/                 чтение настроек и ключей (env, .env)
  model/                  простые структуры данных (Location, Weather, Place, Report)
  httpclient/             асинхронный GET -> JSON через axios4go, отмена и таймаут
  api/                    клиенты GraphHopper, OpenWeather, OpenTripMap
  service/                ЛОГИКА: две асинхронные функции + интерфейсы
  ui/                     консольный интерфейс (только ввод/вывод)
```

Зависимости направлены в одну сторону:

```
main -> ui -> service -> model
main -> api -> httpclient
main -> config
```

`service` не знает ни про HTTP, ни про консоль — только про интерфейсы
`Geocoder`, `WeatherProvider`, `PlacesProvider`. Поэтому его можно тестировать
без сети, а консоль при желании заменить на веб-интерфейс, не трогая логику.

## Как выполнены требования задания

Логика оформлена как **две функции**, каждая сразу возвращает канал
с будущим результатом (аналог `CompletableFuture`):

1. `FindLocations(ctx, query) <-chan LocationsResult` — пункт 2 задания.
2. `LoadReport(ctx, location) <-chan Report` — пункты 4 и 5.

| Требование                                   | Как выполнено                                                            |
|----------------------------------------------|--------------------------------------------------------------------------|
| Независимые вызовы работают одновременно     | Погода и список мест запускаются через независимые async-вызовы               |
| Зависимые вызовы — асинхронная цепочка       | Список мест → описания каждого места (параллельно, не более `PLACES_PARALLEL`) |
| Результаты собираются в общий объект         | `model.Report`; выводится целиком, только когда готов                    |
| Нет блокировок на промежуточных результатах  | Функции возвращают канал сразу; ждёт только `ui` и только конечный результат |



## Устойчивость к сбоям

* Не ответила погода — остальной отчёт всё равно показывается.
* Не загрузилось описание одного места — у него пометка, остальные на месте.
* Ключ API никогда не попадает в тексты ошибок.
* Каждый запрос ограничен таймаутом и отменяется по `Ctrl+C`.
* Горутины не «утекают»: результат кладётся в канал с буфером.

## Тесты

`go test -race ./...` проверяет: разбор ответов API (на локальном тестовом
сервере), параллельность (по времени), сохранение порядка мест, частичные
ошибки, лимит одновременных запросов, сценарий работы консоли и то, что
ключ не попадает в ошибки.

## Асинхронная цепочка

HTTP-клиент вызывает `axios4go.GetAsync` и возвращается сразу. `GetJSON`
принимает callback `done`, который получает результат разбора JSON или ошибку.
API-клиенты предоставляют `SearchAsync`, `CurrentAsync`, `NearbyAsync` и
`DetailsAsync`; они также возвращаются без ожидания сетевых результатов.

`LoadReport` запускает погоду и поиск мест независимо. Callback списка мест
запускает описания; callback каждого описания запускает следующий запрос,
если достигнут лимит параллельности. Ожидания на семафоре и `WaitGroup.Wait`
нет. Счётчики завершённых операций защищены мьютексом. Готовый отчёт отправляется
в буферизованный канал ровно один раз после завершения обеих веток.
Чтение из каналов результатов выполняется только в консоли и тестах.

Контекст передаётся в настоящий `http.Request` через request interceptor
(`req.WithContext`). Поэтому отмена прерывает сетевую операцию, включая чтение
тела ответа. Таймаут запроса задаётся дочерним контекстом и настройкой библиотеки.

Проверка: `go test ./...`; отдельный тест HTTP-клиента проверяет возврат без
ожидания и отмену запроса на стороне локального сервера.


## Интерфейс в браузере

Запустите `go run ./cmd/places` или `places.exe` из папки с `.env`.
Откроется локальная страница приложения. HTML, CSS и JavaScript встроены в exe;
отдельно переносить их не нужно. Ключи API остаются на стороне Go-приложения.

Введите название и выберите карточку найденной локации. Тип объекта берётся
из `osm_value` GraphHopper: например, `bus_stop` отображается как «Автобусная
остановка», `square` — «Площадь». Признак конечной остановки не выдумывается:
обычный `bus_stop` сам по себе не подтверждает, что остановка конечная.

После завершения всех запросов показывается полный отчёт: погода, изображения,
названия и раскрываемые описания мест. Давление показано в мм рт. ст.
Изображения загружаются браузером по ссылкам OpenTripMap; если фотографии нет,
карточка остаётся без изображения. Можно фильтровать готовый список по рейтингу.

HTTP-обработчик ожидает только готовый результат сервисной функции. Асинхронная
цепочка API выполняется в сервисе через callbacks, как и раньше. Браузер ждёт
ответ через fetch, поэтому интерфейс остаётся доступным во время загрузки.
